# Requisitos de infraestructura

| ID        | Requisito de infraestructura                                                                                           | Criterio de aceptación                                                                                             |
| --------- | ---------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| **RI-01** | Los tres servicios de la solución se ejecutan en contenedores independientes: Nginx, API y PostgreSQL.                 | `docker compose ps` muestra los tres servicios en estado `Up`.                                                     |
| **RI-02** | Solo el proxy inverso Nginx está expuesto al exterior. La API y PostgreSQL permanecen dentro de la red interna.        | El servicio PostgreSQL no tiene una sección `ports` y no responde directamente desde el host.                      |
| **RI-03** | Los datos almacenados en PostgreSQL deben persistir después de detener y volver a iniciar los contenedores.            | Después de ejecutar `docker compose down` y `docker compose up -d`, la información almacenada continúa disponible. |
| **RI-04** | La solución debe operar utilizando como máximo 4 GB de memoria RAM para los tres servicios en ejecución.               | `docker stats` permite verificar que el consumo de memoria de los tres servicios no supera el límite establecido.  |
| **RI-05** | La configuración sensible, como las credenciales de la base de datos, no debe estar escrita directamente en el código. | Las credenciales se proporcionan mediante variables de entorno y el archivo `.env` no está versionado en Git.      |
| **RI-06** | La API debe comunicarse con PostgreSQL mediante una red interna de Docker.                                             | La API puede conectarse a PostgreSQL utilizando el nombre del servicio dentro de la red interna.                   |
| **RI-07** | Nginx debe funcionar como proxy inverso y enrutar las peticiones hacia la API.                                         | Una petición realizada al puerto expuesto por Nginx es recibida correctamente por la API.                          |
| **RI-08** | El equipo de desarrollo debe contar con un sistema operativo compatible con Docker Engine y arquitectura de 64 bits.   | La versión del sistema operativo y la arquitectura se verifican mediante comandos del sistema.                     |
| **RI-09** | La solución debe poder levantarse mediante Docker Compose utilizando un único comando.                                 | `docker compose up -d --build` inicia correctamente los tres servicios.                                            |
